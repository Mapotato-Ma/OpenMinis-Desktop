# 08 · 一个能跑的 perf 测试：负载下会偶发红

Status: open
Type: task
优先级：低（上游测试，不在 CI 上红过）

## 现象

`tests/test_perf_and_freshness.py::test_round_tools_run_concurrently` 断言
「两个各 0.3s 的工具并发跑，总耗时 < 0.55s」。理想值 ~0.31s，
余量约 1.8 倍。

实测：本机（iSH）在**同时跑着别的活儿**时它会红（那次同时开着测试服务 +
npm 检查）；空载时一直绿。CI（windows-latest，整套 64 秒）没红过。

## 为什么留着不改

- 它是上游的测试，改阈值 = 又一处偏离，而这里没有真实故障支撑；
- 这条断言本身有价值（并发退化是真 bug 的形态之一）。

## 下次遇到时怎么处理

**先看当时机器在不在忙**。空载下复现不出来就不要当成产品 bug ——
记一笔就行。真要加固，正确做法是同一个测试里先测一次「单工具耗时」，
用 `elapsed_two < single * 1.8` 相对断言，而不是写死 0.55s。
